# YM2608 原生采样率与 48 kHz 声卡

## 1. 原生速率是多少

YM2608 的 FM 部分每个输出样本固定 **144 个主时钟**：

```
f_native = f_master / 144
```

| 主时钟 | f_native | 来源 |
|---:|---:|---|
| 8 000 000 Hz | 55 555.56 Hz | 逆向项目一直用的标称值（整数截断 55 555） |
| 7 987 200 Hz | **55 466.67 Hz** | PC-98 的 3.9936 MHz × 2；`OPN_Chipset` 的 `OPN_OPNA_SAMPLE_RATE` |

两个都不是 48 000。本项目默认 8 MHz（和 `necopn-drv-reverse-main` 的离线渲染一致），
`--clock 7987200` 切到精确 PC-98 值。

> 为什么有 8 MHz 和 7.9872 MHz 两个值？
> 离线项目用 8 MHz 是为了让 fmgen 的 `OPNA_Init` 内部（先 /2 再 /144）得到
> 55 555 Hz；PC-98 实际晶振是 19.968 MHz / 5 = 3.9936 MHz，乘 2 后 /144 得 55 466 Hz。
> 差 0.16%（2.8 音分）。要严格对齐实机录音就用 7 987 200。

## 2. 为什么不让芯片直接跑 48 kHz

芯片的相位/包络/LFO/定时器全部由主时钟驱动，改输出速率等于改主时钟：

- 音高会偏（`f ∝ f_master`）；
- Timer-A 的 836.55 Hz tick 会偏，驱动的软件 LFO/包络跟着偏；
- 55 466 不是 48 000 的整数倍，本来就必须重采样。

所以正确做法是：**芯片按原生速率渲染，最后统一重采样到声卡速率**。

## 3. 重采样实现

`rt_engine.Resampler`：4 点 Catmull-Rom 三次插值，`step = sr_in / sr_out`。

- 55 555 → 48 000：`step = 1.15740`
- 输入/输出比例 ≈ 0.864；一首 3 分钟的歌输出 8.64 M 帧
- 长度：`round(n_in * 48 000 / 55 555)`；因为 4 点插值需要 1 帧历史，
  实际输出最多少 2–3 帧（`tool/selftest.py` 允许 ±3）
- **分块无关**：`Resampler` 自带历史缓冲和分数位置，任意块大小输出逐字节一致
  （自检里 257 帧 vs 整块，结果完全相等）

为什么不用线性插值：线性插值在 20 kHz 附近有明显滚降（-3 dB 左右），
Catmull-Rom 的频响更平，且计算量仍然很小（每样本 ~10 次乘加）。

为什么不在 48 kHz 上做整首歌预渲染：实时版要能 seek/循环，预渲染会引入
分钟级启动延迟；生产者线程按 512 帧块边播边算即可（fmgen 余量 90x）。

## 4. 漂移

| 项 | 误差 |
|---|---|
| 55 555.56 截断成 55 555 | 0.001%（0.017 音分） |
| 55 555 vs 55 466 | 0.16%（2.8 音分） |
| 整数重采样比例累计 10 分钟 | < 10 ms |

44.1 kHz 设备同理：`--sr 44100` 即可，`Resampler` 会自动用 55 555/44 100。

## 5. 声卡侧

本机 Realtek 只接受 48 000（WASAPI/WDM-KS 拒绝 55 555；MME 的“接受”是内部重采样，
延迟上百毫秒）。所以：

```
MIDI → 驱动 → 芯片 55 555 Hz → Catmull-Rom → 48 000 Hz → WASAPI（block 256）
```

实测延迟 22.0 ms，3 秒播放 0 underrun / 0 xrun。
